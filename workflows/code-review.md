# Workflow: Revisão de Código

1. Identificar objetivo, requisitos e critérios de aceite.
2. Examinar diff e contexto dos arquivos afetados.
3. Verificar correção, regressões, segurança, privacidade, desempenho e manutenção.
4. Conferir testes e distinguir resultados observados de resultados presumidos.
5. Registrar cada achado com severidade, evidência, localização e recomendação.
6. Não misturar opinião estilística com defeito funcional sem explicar o impacto.
7. Emitir resultado: `aprovado`, `aprovado com ressalvas` ou `bloqueado`.
8. Se faltarem evidências, declarar a limitação em vez de presumir sucesso.
